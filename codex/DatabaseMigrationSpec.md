# Database Migration Specification

## 目的
- v1のSQLiteスキーマを安全に進化させるための方針を定義する
- 破壊的変更を避け、ユーザーデータを保持する

---

## 方針

### 1. バージョニング
- SQLite `PRAGMA user_version` を使用してスキーマバージョンを管理する
- アプリ起動時に `user_version` を読み取り、必要なマイグレーションを順次適用する

### 2. マイグレーションの原則
- 追加系（列追加・テーブル追加）を優先
- 破壊的変更（列削除・型変更）は原則禁止
- どうしても必要な場合は新テーブル作成 → データ移行 → 旧テーブル削除の段階的移行

### 3. マイグレーション実行タイミング
- アプリ起動時に必ず実行
- エラー時はロールバックせず、起動を中断してエラーを通知する（v1）

### 4. 変換・バックフィル
- `NULL` 許容列追加時はデフォルト値を設定
- 既存行の派生列はバックフィルで埋める

---

## バージョン戦略（例）

### v1.0.0 → schema_version = 1
- 初期スキーマ

### v1.1.0 → schema_version = 2
- 新列追加、インデックス追加など非破壊の拡張

---

## マイグレーション実装規約

- 1バージョンごとにSQL配列を定義
- 低いバージョンから順に適用

例：
```
const migrations = {
  1: [/* create tables */],
  2: [/* add columns / indexes */]
}
```

---

## テスト観点
- 旧バージョンDBから最新へのアップグレードが成功する
- 途中バージョンからのアップグレードが成功する
- 空DBの初期化が成功する
