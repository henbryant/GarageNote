# Database Migration Specification (Room)

## 目的
- v1のSQLiteスキーマを安全に進化させるための方針を定義する
- 破壊的変更を避け、ユーザーデータを保持する

---

## 方針

### 1. バージョニング
- Room の `version` を使用してスキーマバージョンを管理する
- アプリ起動時に `Migration` を順次適用する

### 2. マイグレーションの原則
- 追加系（列追加・テーブル追加）を優先
- 破壊的変更（列削除・型変更）は原則禁止
- どうしても必要な場合は新テーブル作成 → データ移行 → 旧テーブル削除の段階的移行

### 3. マイグレーション実行タイミング
- Room の `databaseBuilder` で `addMigrations(...)` を必ず設定
- エラー時はアプリ起動を中断してエラーを通知する（v1）

### 4. 変換・バックフィル
- `NULL` 許容列追加時はデフォルト値を設定
- 既存行の派生列はバックフィルで埋める

---

## バージョン戦略（例）

### v1.0.0 → schema_version = 1
- 初期スキーマ

### v1.1.0 → schema_version = 2
- 新列追加、インデックス追加など非破壊の拡張

---

## マイグレーション実装規約

- 1バージョンごとに `Migration` を定義
- 低いバージョンから順に適用

例：
```
val MIGRATION_1_2 = object : Migration(1, 2) {
  override fun migrate(db: SupportSQLiteDatabase) {
    // add column / index
  }
}
```

---

## テスト観点
- 旧バージョンDBから最新へのアップグレードが成功する
- 途中バージョンからのアップグレードが成功する
- 空DBの初期化が成功する
